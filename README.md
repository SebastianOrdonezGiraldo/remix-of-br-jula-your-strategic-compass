# Remix of Brújula: Your Strategic Compass

Quiero que construyas una aplicación web moderna llamada Brújula.

Brújula no es un sitio web institucional, un chatbot ni un portafolio digital.

Es una experiencia interactiva que ayuda a empresas y organizaciones a descubrir cómo una universidad puede apoyarlas a resolver sus desafíos.

La experiencia debe sentirse como una conversación con un consultor estratégico.

No como un formulario.

No como una página de ventas.

No como un catálogo.

La prioridad absoluta es la experiencia del usuario.

 

OBJETIVO

Construir un micrositio responsive donde una organización pueda:

expresar un desafío,

explorar alternativas,

descubrir rutas de solución,

conocer capacidades de la universidad,

identificar oportunidades de colaboración,

decidir si desea establecer contacto.

La experiencia debe ser intuitiva y generar confianza desde el primer segundo.

 

FILOSOFÍA

Toda la experiencia debe construirse alrededor de esta frase:

Las mejores soluciones empiezan entendiendo el desafío.

Brújula escucha antes de recomendar.

Nunca empieza mostrando servicios.

Siempre empieza comprendiendo el problema.

 

IDENTIDAD

Brújula debe sentirse:

✔ Moderna

✔ Elegante

✔ Humana

✔ Estratégica

✔ Profesional

✔ Cercana

Nunca institucional.

Nunca comercial.

Nunca fría.

 

ESTILO VISUAL

Inspirarse en productos digitales modernos como:

Notion

Linear

Airbnb

Stripe

Apple

No copiar su apariencia.

Inspirarse en:

simplicidad,

espacios amplios,

tipografía limpia,

jerarquía visual,

microinteracciones.

 

PALETA

Fondos blancos.

Mucho espacio.

Texto gris oscuro.

Azul institucional como color principal.

Colores secundarios únicamente para pequeños acentos.

El diseño debe convivir correctamente con dos logotipos institucionales cuyos colores son gris y blanco.

No competir visualmente con ellos.

 

TIPOGRAFÍA

Inter

o

Manrope

Todo el sistema debe utilizar una sola familia tipográfica.

 

NAVEGACIÓN

Toda la aplicación debe sentirse como una conversación.

Evitar cambios bruscos entre páginas.

Las preguntas deben aparecer progresivamente.

La navegación debe desarrollarse dentro de un mismo flujo.

 

PANTALLA INICIAL

Mostrar:

Logos institucionales.

Nombre:

BRÚJULA

Subtítulo:

Las mejores soluciones empiezan entendiendo el desafío.

Texto introductorio:

"No queremos empezar mostrándote un portafolio. Queremos comprender el desafío de tu organización para ayudarte a encontrar las mejores alternativas."

Campo principal:

¿Qué desafío quieres resolver hoy?

Placeholder:

Ejemplo:

"Quiero reducir mis tiempos de entrega."

Botón principal:

Encontrar mi ruta

 

TARJETAS DE DESAFÍOS

Mostrar tarjetas grandes, visuales y fáciles de seleccionar.

Cada una debe tener un ícono moderno, un título y una frase breve.

Las categorías iniciales son:

📈 Ventas y Marketing

⚙ Productividad y Procesos

🤖 Transformación Digital e Inteligencia Artificial

👥 Talento Humano y Liderazgo

💰 Finanzas

📦 Logística

🛡 Calidad

🌱 Sostenibilidad

🚀 Innovación

📊 Planeación Estratégica

🌎 Internacionalización

❤️ No estoy seguro

Las tarjetas deben tener esquinas redondeadas, sombra suave y elevarse ligeramente al interactuar.

 

TARJETAS SECUNDARIAS

Debajo del bloque principal mostrar tres tarjetas horizontales con mayor protagonismo.

Explorar capacidades

Descripción:

"Conoce distintas formas en las que podemos apoyar el crecimiento de tu organización."

Ejemplos visibles:

Formación a la medida

Consultoría

Programas académicos

Educación continua

 

Construyamos juntos

Descripción:

"Descubre oportunidades para desarrollar proyectos, prácticas empresariales, innovación aplicada y trabajo colaborativo con la universidad."

 

Beneficios para aliados

Descripción:

"Explora becas, descuentos y beneficios exclusivos para organizaciones aliadas."

 

CONVERSACIÓN

Cuando el usuario escriba un desafío o seleccione una tarjeta:

NO cambiar de página.

Continuar la conversación debajo.

La aplicación debe responder primero con empatía.

Ejemplo:

"Gracias. Muchas organizaciones enfrentan un desafío similar."

Después realizar únicamente las preguntas necesarias para comprender mejor el contexto.

Nunca más de tres preguntas consecutivas.

 

MOTOR DE RECOMENDACIONES

Las organizaciones hablan de síntomas.

Brújula debe identificar capacidades.

Nunca responder únicamente por palabras clave.

Interpretar el contexto.

Ejemplo:

"No vendo suficiente."

Puede relacionarse con:

marketing

estrategia comercial

diferenciación

conocimiento del cliente

propuesta de valor

Generar rutas.

No respuestas.

 

RESULTADO

Nunca mostrar:

Servicios.

Mostrar:

Tu Ruta Recomendada

Cada ruta debe construirse como un recorrido visual.

Ejemplo:

Comprendimos tu desafío

↓

Fortalecer capacidades comerciales

↓

Explorar herramientas de marketing

↓

Proyecto aplicado

↓

Capacitación especializada

↓

Beneficios disponibles

↓

Construyamos juntos

Cada etapa debe mostrarse mediante tarjetas elegantes.

 

EXPLORACIÓN LIBRE

El usuario puede abandonar la conversación cuando quiera.

Debe poder navegar libremente.

Nunca bloquear la navegación.

 

BENEFICIOS

Crear una sección independiente donde posteriormente puedan agregarse:

Becas empresariales

Descuentos

Convenios

Beneficios para empleados

Educación continua

Otros incentivos

Diseñar esta sección para que sea fácilmente administrable.

 

CAPACIDADES

No organizar la información por carreras.

Organizarla por capacidades.

Ejemplos:

Fortalecer ventas.

Optimizar procesos.

Transformación digital.

Automatización.

Innovación.

Liderazgo.

Gestión ambiental.

Planeación.

Logística.

Calidad.

La universidad aparece únicamente como respaldo de esas capacidades.

 

EXPERIENCIA

Cada interacción debe aumentar la confianza.

Nunca debe sentirse que la universidad intenta vender algo.

La sensación final debe ser:

"Comprendieron mi situación."

 

COMPONENTES

Utilizar un sistema moderno basado en:

Cards

Badges

Accordions

Timeline

Progress Indicator

Search

Floating Action Button

Responsive Grid

 

ANIMACIONES

Muy discretas.

Fade.

Slide.

Hover.

Expansión de tarjetas.

La aplicación debe sentirse viva sin distraer.

 

MÓVIL

Diseñar primero para teléfonos móviles.

El principal punto de entrada será un código QR entregado durante visitas empresariales.

La experiencia móvil debe ser excelente.

 

DESARROLLO

Construir el proyecto utilizando buenas prácticas.

Código organizado.

Componentes reutilizables.

Arquitectura escalable.

Preparar el proyecto para incorporar posteriormente una base de conocimiento y un motor de inteligencia artificial.

 

RESULTADO ESPERADO

No quiero una landing page.

No quiero un catálogo.

Quiero un producto digital con apariencia de startup tecnológica, que pueda evolucionar hacia un asistente inteligente para conectar organizaciones con las capacidades de la universidad.

Construye únicamente un prototipo funcional de alta fidelidad (MVP), priorizando la experiencia de usuario sobre la cantidad de funcionalidades. Utiliza datos de ejemplo donde sea necesario y diseña la arquitectura pensando en futuras iteraciones
